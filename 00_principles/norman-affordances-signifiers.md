# Don Norman — Affordances, Signifiers & Human-Centered Design

Primary source: *The Design of Everyday Things* (originally 1988, revised editions later). Norman is a cognitive scientist; the book remains one of the most influential texts in product design, interaction design, and UX.

## Core Concepts

### Affordances
The relationship between the properties of an object and the capabilities of the agent that determine how the object can possibly be used. Affordances are not properties of the object alone; they are relationships.

- A chair affords sitting (for most humans).
- A flat plate on a door affords pushing; a handle affords pulling or turning.

### Signifiers
Any mark or sound, any perceivable indicator that communicates appropriate behavior to a person. Signifiers are more important in design practice than pure affordances because they tell the user what actions are possible and where.

- A label, an icon, a depression that suggests "press here", a cursor change.

### Mapping
The relationship between controls and their effects. Natural mappings (spatial or cultural) reduce the need for memory and training.

### Feedback
Sending information back to the user about what action has been done and what has been accomplished. Immediate, clear feedback is essential.

### Conceptual Models
The mental model the user forms of how the system works. Good design makes the system’s conceptual model match the user’s expectations or easily learnable.

### Constraints
Physical, cultural, semantic, and logical constraints that guide possible actions and reduce errors.

## Dos
- Make the system’s state and possible actions visible.
- Use natural mappings and clear signifiers.
- Provide continuous, informative feedback.
- Design for error: prevent, detect, and recover gracefully.
- Test with real users; the designer’s model is not the user’s model.

## Don’ts
- Rely on the user’s memory for critical actions.
- Hide important controls or status information.
- Create false affordances (things that look clickable but aren’t, or vice versa).
- Assume users will read manuals or discover features through exploration alone.

## Connection to Visual Styles
- Supports clarity-focused styles (Swiss, Minimalism).
- Conflicts with pure decorative maximalism when it reduces understandability.
- Essential for any UI/UX work regardless of visual style.
